Open **Settings** > **Integrations**. Choose a connection based on what you want to do with your workspace data.

| Goal | Connection |
| --- | --- |
| Send lead alerts | [Slack](/integrations/slack) |
| Send leads to an outreach destination | [HeyReach](/integrations/heyreach) |
| Start another workflow | [Webhook](/integrations/webhook), [Clay](/integrations/clay), [n8n](/integrations/n8n), or [Zapier](/integrations/zapier) |
| Work from an AI client | [Claude](/integrations/claude), [Codex](/integrations/codex), or another [compatible MCP client](/integrations/ai-clients) |
| Attribute booked meetings | [Google Calendar](/integrations/google-calendar) |
| Analyze an aggregate audience | [Ordinal](/integrations/ordinal) |
| Export an advertising audience | [Meta Ads](/integrations/meta-ads) |
| Read data from application code | [REST API](/api-reference/quickstart) |

## Connect, then choose delivery

A successful connection does not mean leads are being sent. For lead-delivery integrations, configure [routes](/integrations/routes) that select an audience, destination, and delivery mode.

Review the route and connection state before relying on automatic delivery. Use a test event to check the receiving system, then inspect a real lead's delivery result.

Connection management, route changes, and API-key creation can have different permission requirements. Use the actions available to your current role and ask an admin when access is missing.
