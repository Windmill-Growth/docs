Use API & MCP when you want another tool to read workspace data from `traxy` or when you want an AI coding client to use `traxy` tools through MCP.

API keys are for public REST API calls. MCP uses OAuth, so you do not need to paste an API key into your MCP client.

API & MCP access is included with paid workspaces. If your workspace needs an upgrade, `traxy` shows that on the integration page.

## Before you connect API & MCP

Owners and admins can create or revoke API keys. Members can still use the MCP setup instructions when workspace access allows it.

Make sure you know:

- which external system will use the API key
- which scopes the system needs
- where your team stores production secrets
- which MCP client you want to connect

Default API keys include standard read access for leads, analytics, ICP, Watchlist, content, integrations, sync status, and workspace access.

Contact data is sensitive. Select it only when the integration needs it.

Audience analytics scopes are available for approved aggregate audience workflows. Use the dedicated [Ordinal integration](/using-traxy/integrations/ordinal) when you are connecting Ordinal.

## Create an API key

1. Open **Integrations**.
2. Open **API & MCP**.
3. Open the **API keys** tab.
4. Click **Create key**.
5. Add a clear name, such as `Production integration`.
6. Select the scopes the integration needs.
7. Click **Create key**.
8. Copy the key from the **API key created** dialog.
9. Store the key in your team's secret manager.

`traxy` shows the full key only once. After you close the dialog, you can see the key name, status, scopes, preview, created date, and last used date, but not the full secret.

Use the key as a bearer token for `traxy` public API calls.

```http
Authorization: Bearer trxy_live_...
```

Open the [API reference](/using-traxy/integrations/api-mcp/reference) when you are ready to review endpoints, parameters, scopes, and response shapes.

## Choose API scopes

Use the smallest scope set that supports your workflow.

- `leads:read` lets the integration read visible lead data.
- `leads:contact_read` lets the integration read contact fields. This scope is sensitive.
- `analytics:read` lets the integration read dashboard and post analytics.
- `icp:read` lets the integration read the active ICP summary.
- `watchlist:read` lets the integration read watched profiles and summaries.
- `content:read` lets the integration read visible content feed posts.
- `integrations:read` lets the integration read safe integration connection and delivery status.
- `sync:read` lets the integration read qualification and engagement sync status.
- `workspace:read` lets the integration read workspace access status.
- `audience_analytics:read` lets an approved integration read aggregate audience analytics.
- `audience_analytics:request` lets an approved integration request audience discovery.

For Ordinal setup, use the dedicated [Ordinal integration](/using-traxy/integrations/ordinal) instead of creating a general API key here.

## Revoke an API key

Revoke a key when it is no longer used, when a vendor changes, or when you think the key was exposed.

1. Open **Integrations**.
2. Open **API & MCP**.
3. Open the **API keys** tab.
4. Find the key.
5. Click **Revoke**.
6. Confirm the change.

Existing clients using that key lose access immediately.

## Connect MCP

Use MCP when you want an AI client to ask `traxy` for workspace context through tools.

The production MCP endpoint is:

```text
https://api.traxy.ai/api/v1/mcp
```

The **MCP** tab supports:

- Claude Code
- Codex
- Cursor
- OpenCode

1. Open **Integrations**.
2. Open **API & MCP**.
3. Open the **MCP** tab.
4. Choose your client.
5. Copy the setup command or config from `traxy`.
6. Paste it into your MCP client.
7. Approve the OAuth flow when your client opens it.
8. Confirm the client appears connected.

Use **Copy setup prompt** when you want `traxy` to generate client-specific setup instructions. Use **Copy skill** when you want to give the client durable guidance about safe `traxy` tool usage.

After OAuth approval, the client can list and run `traxy` tools based on your workspace permissions.

## Client setup notes

For Claude Code, copy the command from `traxy`. It uses this shape:

```sh
claude mcp add --transport http --scope user traxy "https://api.traxy.ai/api/v1/mcp"
```

Then open Claude Code, use `/mcp`, and approve `traxy` in the browser when OAuth starts.

For Codex, copy the command from `traxy`. It uses this shape:

```sh
codex mcp add traxy --url "https://api.traxy.ai/api/v1/mcp"
```

Then open Codex and verify the connection with `/mcp`. If Codex reports that the server is unauthenticated, start the OAuth login from Codex and approve `traxy`.

For Cursor, copy the config into `.cursor/mcp.json`, restart Cursor, and approve `traxy` when Cursor starts OAuth.

```json
{
  "mcpServers": {
    "traxy": {
      "type": "http",
      "url": "https://api.traxy.ai/api/v1/mcp"
    }
  }
}
```

For OpenCode, copy the config into `~/.config/opencode/opencode.json`. If OpenCode does not prompt automatically and reports the server is unauthenticated, run:

```sh
opencode mcp auth traxy
```

Use the command or config shown in `traxy` as the source of truth. It includes the correct MCP endpoint for your environment.

## MCP tools

Your MCP client lists the available tools after you connect. Tools return only data your workspace permissions allow.

- **traxy\_get\_mcp\_connection\_status** returns connection and auth diagnostics, scope values, and protocol versions.
- **traxy\_list\_leads** returns visible leads.
- **traxy\_list\_lead\_signals** returns lead engagement signals with safe lead, watched-profile, and post context.
- **traxy\_list\_account\_reports** returns account-level lead summaries.
- **traxy\_get\_account\_report** returns one account report with top visible leads.
- **traxy\_get\_watchlist\_profile** returns one watched profile with company, profile, and sync fields.
- **traxy\_get\_agent\_status** returns agent state, the active or latest run, preview, and eligibility.
- **traxy\_get\_agent\_budget\_status** returns configured and enabled state, daily usage, credit usage, projection, and preview allowance.
- **traxy\_list\_agent\_runs** returns recent Agent run summaries.
- **traxy\_list\_agent\_candidates** returns safe visible candidates plus aggregate locked counts.

## Filter MCP tool results

Use filters to narrow tool results before the client processes them.

### traxy\_list\_leads

- `origin=agent|watchlist|all` filters leads by where they were found.

The older `foundBy` parameter is deprecated but still accepted. `foundBy=agent` and `foundBy=onboarding_preview` normalize to `origin=agent`. Use `origin` in new integrations.

### traxy\_list\_lead\_signals

- `origin=agent|watchlist|all`
- `engagementType`
- `engagementTypes`
- `companyNames`
- `profileType`
- `relationshipLabel`
- `minIcpMatchPercent`
- `maxIcpMatchPercent`

Existing selectors still work: `leadId`, `monitoredProfileId`, `monitoredProfileIds`, `postId`, `dateFrom`, `dateTo`, `disposition`, and `query`.

### traxy\_list\_account\_reports and traxy\_get\_account\_report

- `accountId`
- `companyName`
- `minIcpMatchPercent`
- `maxIcpMatchPercent`
- `dateFrom`
- `dateTo`
- `query`
- `sort=latestSignalAt|leadCount|averageIcpMatchPercent|accountName`
- `sortDirection=asc|desc`

### traxy\_get\_watchlist\_profile

- `monitoredProfileId`

### traxy\_list\_agent\_candidates

- `runId`
- `source=latest_agent_run|latest_preview`
- `limit`
- `offset`

## Keep access safe

Treat API keys like passwords.

- Store API keys in a secret manager.
- Do not paste API keys into MCP config.
- Do not ask an MCP client to reveal API keys, OAuth tokens, authorization headers, emails, phone numbers, LinkedIn profile URLs, raw comments, or raw error messages.
- Revoke keys you no longer use.
- Create separate keys for production and testing.
- Review **Last used** before removing old keys.

MCP grants use OAuth instead of API keys. If you no longer want a client to access `traxy`, remove the MCP connection in that client and reconnect only when needed.
