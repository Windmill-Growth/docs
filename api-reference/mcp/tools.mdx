---
title: "MCP tools"
description: "Reference the public traxy MCP tool catalog, required scopes, and action requirements."
---

The public catalog contains 234 tools before scope and workspace filtering. Use `tools/list` to discover the tools and argument schemas your connection can actually use.

Each row lists all required scopes. Current workspace roles, product access, and action-specific checks still apply. Seeing a tool in the catalog does not grant permission to use it in every workspace.

Tool names retain `watchlist`, `organization`, and other established names where those are part of the public contract. In the app, watchlist profiles are tracked people or companies, and an organization is a workspace.

## Confirm actions

Select the workspace, target, and action before making a write request. Use the returned preview and current schema rather than copying arguments from another tool.

- `traxy_start_agent_run` and `traxy_qualify_linkedin_post` require `confirmLeadUsage: true` after the user agrees that new qualified people may consume pipeline capacity.
- `traxy_apply_lead_action` supports `snooze`, `done`, `good`, `bad`, and `client`. The `done` action needs `confirmDone: true`. Preview bulk changes before applying them.
- Contact lookup needs an explicit request. Phone lookup applies only to eligible leads after activation. Saving manually supplied contact details is separate from enrichment.
- Read the current ICP or Signal Brief before updating it. Use its revision in requests that require one. Supplied arrays replace their earlier values; omitted fields stay unchanged.
- Preview campaign launch, message sending, billing, and destructive actions before confirming the intended change. A draft or preview does not authorize execution.
- Webhook destinations and delivery routes can send contact data outside traxy. Confirm the user’s intended host, audience, and destination before creating, changing, enabling, or sending to them.
- A queued delivery or lookup is not proof of completion. Read the resulting state before repeating a request.

The former `confirmCreditSpend` argument is not accepted. Sending it returns `validation_failed`; use only the current schema. The capacity tool replaces the former Agent budget-status tool.

See [workspace selection](/api-reference/mcp/workspaces), [authentication and scopes](/api-reference/authentication), and [error handling](/api-reference/pagination-and-errors) when building a client.
